Julia layout and mapping workflow

The current island layout is unchanged. Open the world map. The tag owid-clean-layout-baseline-v1 preserves that baseline.

The supported workflow now runs from a cartogram CSV, Kontur, and Natural Earth to a resized layout, an H3 mapping, and population-density Arrow files. It uses Julia. Tile count and country set are inputs, not fixed constants. See owid-layout/workflow.md in the repository for commands and input formats.

Checks

  • 254 supported Julia tests pass. These include a custom five-tile regional cartogram and a custom country code.
  • The full-world layout was regenerated. Its cell file is byte-identical to the baseline.
  • The H3-5 adapter checked all 32,957,699 native cells. It produced 400,161 component/H3 fragments, 244 population pools, and 54,967 target tiles. Population accounting.
  • Real fits for Malaysia, Brunei, and Fiji cover 236 tiles and four separate population pools. Source weight sums differ from one by less than 1e-9. Relative target error is below 1e-6. No transport crosses a population-pool boundary. Regional fit checks.
  • The exported Arrow files loaded in headless H3-MON without page errors or failed requests. Browser checks. The image below was inspected.

This is a regional export test, not a new full-world deployment. The browser used local file interception; no H3-MON defaults were changed. City labels and border-aware fitting are not part of this workflow.
